Why can one resident page be enough for the sequential test, even when pos + 1
crosses a page boundary?
Answer: One resident page is enough for the test because the program accesses
array elements one after another. After accessing an element the program moves forward.
Does not go back to the previous elements. When `pos + 1` moves to a page the program
tries to access that new element. That action causes a page fault because the new page is
not in memory. The SIGSEGV handler takes care of that fault by removing the page and
adding the new page that contains the element. So one page needs to be in memory at any
time even when the access moves to a new page.
Why is it unsafe to call `printf` inside a signal handler? Which functions in your
handler are async-signal-safe?
Answer: It is not safe to use `printf()` inside a handler because `printf()` is not an asyncsignal-safe function. It uses buffers and shared data that might be in use when a signal
stops the program. Trying to use `printf()` again in the handler can cause deadlocks,
broken output or strange behavior.
Async-signal-safe functions can be used safely in a handler. Examples are `write()`
`read()` `)` and `_exit()`. In our code the operations like checking addresses and aligning
pages do not use library functions. However functions like `mmap()` and `munmap()` are
not guaranteed to be async-signal-safe. Also functions like `calculate_sqrts()` depend on
how they're written. So it is important to be careful with what's done inside a signal
handler.
What would happen if the handler did not check that the fault address lies inside the
Table?

Checking if the fault address is inside the table is important because a SIGSEGV can
happen for reasons not just because of the table. If the handler does not check it might
think every segmentation fault is caused by the table.
This could lead to mapping memory at the place changing other parts of memory or
causing more faults. This could result in data, program problems or a loop of faults.
Checking the address makes sure the handler only deals with faults, from the table and
lets other faults be handled normally.
